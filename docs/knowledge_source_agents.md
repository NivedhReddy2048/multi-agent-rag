## 1. Overview & Architecture

Phase 2.3 introduces independent, modular **Knowledge Source Agents** and the **Parallel Knowledge Orchestrator**.

Following the plan generated by the Knowledge Planner (Phase 2.2), the system fans out concurrent retrieval calls across selected agents, collecting standardized `KnowledgeResult` objects into a unified `KnowledgeCollection`.

```
Student Query
     │
     ▼
[ LangGraph Planning Graph ]
     │
     ├─► 1. Intent Node
     ├─► 2. Difficulty Node
     ├─► 3. Source Selection Node
     ├─► 4. Retrieval Strategy Node
     ├─► 5. Output Planning Node
     ├─► 6. Execution Plan Node
     │
     ▼
[ ExecutionPlan Contract ]
     │
     ▼
[ LangGraph Knowledge Collection Node ]
     │
     ▼
[ KnowledgeOrchestrator ] ──(ThreadPoolExecutor Parallel Fan-Out)──►
     ├─► DocumentKnowledgeAgent (Vector DB + BM25 Hybrid)
     ├─► GeneralAIKnowledgeAgent (Multi-LLM Failover)
     ├─► TrustedWebKnowledgeAgent (Tavily + DDG Fallback)
     ├─► WikipediaKnowledgeAgent (Wikipedia Summaries)
     ├─► SemanticScholarKnowledgeAgent (Academic Literature)
     ├─► ArxivKnowledgeAgent (Preprint Literature)
     ├─► GoogleBooksKnowledgeAgent (Textbook Previews)
     ├─► YoutubeKnowledgeAgent (Educational Videos)
     └─► GithubKnowledgeAgent (Code Repositories)
     │
     ▼
[ Standardized KnowledgeCollection Contract ]
     │
     ▼ (Developer Panel / Inspection & Phase 2.4 Verification Input)
```

## 2. Standardized Domain Contracts

### `KnowledgeResult` Model
Every agent converts provider-specific responses into a unified `KnowledgeResult`:
```python
class KnowledgeResult(BaseModel):
    provider: str
    source_type: SourceType
    title: str
    content: str
    summary: Optional[str] = None
    url: Optional[str] = None
    authors: List[str] = []
    published_date: Optional[str] = None
    confidence: float = 1.0
    latency_ms: float = 0.0
    metadata: Dict[str, Any] = {}
    raw_response: Optional[Any] = None
```

### `KnowledgeCollection` Container Model
```python
class KnowledgeCollection(BaseModel):
    query: str
    execution_plan_id: str
    collection_timestamp: str
    total_latency_ms: float
    sources_requested: List[str]
    sources_completed: List[str]
    sources_failed: List[str]
    results: List[KnowledgeResult]
    provider_latencies: Dict[str, float]
    metadata: Dict[str, Any]
```

## 3. Modular Knowledge Source Agents (`agents/sources/`)

All agents implement `BaseKnowledgeAgent` (`initialize()`, `execute()`, `health()`, `shutdown()`):

| Agent Name | Source Type | Underlying Technology |
| :--- | :--- | :--- |
| `DocumentKnowledgeAgent` | `internal_document` | `RetrievalEngine` (Chroma Vector DB + BM25) |
| `GeneralAIKnowledgeAgent` | `general_ai` | `LLMManager` (Gemini → Groq → Cohere → Mistral) |
| `TrustedWebKnowledgeAgent` | `trusted_web` | Tavily API + DuckDuckGo fallback |
| `WikipediaKnowledgeAgent` | `wikipedia` | Wikipedia API Wrapper |
| `SemanticScholarKnowledgeAgent` | `semantic_scholar` | Semantic Scholar REST API |
| `ArxivKnowledgeAgent` | `arxiv` | arXiv API Feed Parser |
| `GoogleBooksKnowledgeAgent` | `book` | Google Books API v1 |
| `YoutubeKnowledgeAgent` | `video` | YouTube Data API v3 |
| `GithubKnowledgeAgent` | `github_repo` | GitHub REST API v3 Search |

---

## 4. Fault-Tolerant Parallel Execution (`core/orchestrator/knowledge_orchestrator.py`)

- **Concurrency**: `ThreadPoolExecutor` executes all planner-requested agents simultaneously.
- **Fault-Tolerance**: If a single agent fails or times out, the exception is caught, logged in `sources_failed`, and the orchestrator continues with partial results.
- **Strict Isolation**: No agent has awareness of any other agent.

## 5. Telemetry & Analytics

Collection performance is logged to SQLite via `ConversationMemory.record_collection_telemetry()`:
- `executed_sources`
- `successful_sources`
- `failed_sources`
- `parallel_execution_time`
- `individual_latencies`
- `provider_failures`

## 6. Next Phase Roadmap (Phase 2.4 — Knowledge Verification Engine)

In Phase 2.4, the raw `KnowledgeCollection` produced here will feed into:
1. **CRAG Evidence Verification**: Assessing factual consistency of retrieved chunks across sources.
2. **Cross-Source Quality Ranking**: Scoring sources based on relevance and authority.
3. **Discrepancy Detection**: Identifying contradictions across web, document, and research sources.
